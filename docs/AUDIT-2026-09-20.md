# Forge Conductor adversarial pre-release audit — 2026-09-20

## Outcome

The current `0.10.0 (2)` source was audited before release work. Four confirmed
source defects and one defense-in-depth DOM risk were corrected. No confirmed
critical or high-severity defect remains open in the audited source. This is a
source and development-build qualification result, not a release archive,
notarization, installation, public-distribution, or shipment result.

## Scope and method

The audit inspected the canonical workspace and SwiftPM graph, HTTP request
parsing and every dashboard/Manager mutation route, browser rendering sinks,
durable credential handling, process ownership and shutdown, filesystem and
subprocess boundaries, dependency closure, embedded-secret patterns, Release
build settings, and the current test inventory. It also exercised the focused
reproducers, both SwiftPM products, the canonical Debug workspace build, Xcode
static analysis, repository hygiene, and the full Swift test suite.

The package has no external Swift package dependency. Secret-pattern review
found only deliberate redaction logic and test fixtures; no production key or
token was found. Existing `try!`, `fatalError`, and `preconditionFailure` sites
were reviewed as locally constructed invariant boundaries rather than
attacker-controlled parsing paths.

## Closed findings

| Severity | Evidence | Finding | Correction |
| --- | --- | --- | --- |
| High | E1 | Loopback session prune/close accepted any request that passed Host/origin/JSON policy; browser Manager controls had no page-instance capability and could not safely receive the durable Manager bearer. | Each dashboard server now generates a 256-bit process-local mutation token, injects it only into `/control` and `/manager`, compares it exactly with bounded constant-time work, and accepts it only for the five visible Manager controls plus session prune/close. Durable bearer authorization remains valid for native clients and is never embedded in HTML. |
| Medium | E1 | `POST /api/manager/stjornarvald/notices/pending` was classified as an unauthenticated read although it durably reserves notice delivery rows. | The route is now classified as a mutation and requires the owner-only Manager bearer. |
| Medium | E1 | Dashboard port inspection waited for `lsof` before draining its pipe, had no deadline/output cap, and could run the same probe twice. | Port inspection now uses the shared process runner with concurrent pipe drainage, a two-second deadline, a 128 KiB output ceiling, explicit truncation/timeout rejection, and one holder query. |
| Medium | E1 | Shipped Release targets could inherit base entitlements; the Core Release target explicitly enabled testability. | The app, Core framework, and runtime launcher Release configurations now set `CODE_SIGN_INJECT_BASE_ENTITLEMENTS=NO`; Core no longer enables Release testability. A graph test enforces both rules for every shipped Release target. |
| Low | E2 | A status value entered HTML without escaping, and a session identifier was interpolated into inline JavaScript. Client code also treated 4xx mutation responses as success. | Dynamic status text is escaped, session controls use data attributes and registered listeners, and every non-2xx response is surfaced as an error. |

The packaged telemetry footer also now says `LOOPBACK · READ-ONLY TELEMETRY`
instead of claiming that the complete product has no authorization boundary.

## Verification

- Dashboard security: 11 tests passed, including missing/wrong/exact token,
  token rotation, route scoping, durable-bearer compatibility, HTML nonleakage,
  4xx handling, and inline-handler removal.
- Port ownership: 3 lifecycle cases plus the focused free-port case passed.
- Release project policy: the focused signing/testability graph test passed.
- Stjornarvald authorization: the focused classification and route-integration
  cases passed.
- Swift products: `forge-conductor` and `forge-conductor-app` built.
- Canonical Xcode Debug app build passed. Xcode static analysis passed without
  a project diagnostic.
- Full suite: 1,691 XCTest cases passed with 12 explicit environment/fixture
  skips and zero failures. The zero-test Swift Testing runners are not included
  in that count.
- No source or test membership change was required: every edited Swift file and
  test already belongs to the canonical Xcode graph. The project change is the
  deliberate Release-configuration hardening above.

## Boundaries retained for release work

The 12 declared skips remain skips rather than passes. They cover prepared
candidate/peer fixtures, live external-provider configuration, disposable
credential fixtures, and parent-harness-only cases. Existing physical
VoiceOver, second-memory-capacity, installed distinct-process protected-service,
exact-artifact signing/notarization/stapling/Gatekeeper, and public-download
gates remain recorded in the qualification status. None was executed or waived
by this audit.
