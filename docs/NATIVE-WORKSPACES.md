# Native custom workspaces

Source target: **0.44.0 (60)**. Custom layouts belong to each existing view. They do not combine panels from different views.

All 13 main views provide **Customize Layout**, a layout menu, **Panels** and **Restore Default**. Drag a panel header to move it and its lower-right grip to resize it. The close button hides a panel; the Panels menu shows it again. Geometry, stacking and visibility changes persist after completed gestures or explicit actions. Escape cancels a drag. Focused headers accept arrow-key movement in 10-point steps and Option-arrow resizing; focused resize grips accept arrow-key resizing.

**Save Layout As…** creates a separate named layout. Rename and Delete apply to the active saved layout. **Restore Default** selects the original composition without deleting saved layouts. Switching layouts within a view retains the page's state owner. Manager sections and Rune Forge detail modes retain their own layouts inside those existing views.

## Ownership and limits

`NativeWorkspacePreferences` has one application owner, shared with the ordinary Settings scene. It stores schema 1 data under `forge.workbench.workspaces.v1` in the existing workbench defaults suite. Validation precedes storage or publication. Invalid or unsupported stored data is retained until an explicit successful layout edit.

The collection allows at most 32 saved layouts across 32 view namespaces, 64 panels per view and 512 KiB stored data. Names are limited to 96 UTF-8 bytes and must be unique within the view. Each panel has finite descriptor-specific minimum/maximum dimensions and must fit its finite canvas. Catalog membership is checked before restoration.

The canvas owns transient gestures. Native panel hosts remain stable while moving, resizing and switching saved layouts. Initially hidden panels are not constructed. Previously shown hidden hosts remain bounded by the panel catalog. Dismantling removes hosts and callbacks; switching layout identity cancels an outstanding gesture. Stale callbacks cannot mutate a different active layout.

Hiding a panel cancels its pending transient gesture when the canvas applies visibility. The frame callback also checks the current panel’s visibility before the existing active-layout identity check, so a late callback before native apply cannot persist hidden geometry. Showing the panel retains its existing host and permits a fresh gesture.

Pointer and keyboard edits share the pending gesture: arrows update bounded native geometry without saving it, and rebase a separate pointer anchor at the last observed point so subsequent pointer input retains those changes. The original frame remains the Escape/Hide/layout rollback frame. Mouse-up publishes the completed frame; standalone arrows retain immediate persistence.

Existing page state, selections, drafts, actions and confirmation sheets remain in the page owner. Hidden Compute suspends rendering. Dashboard, Projects, Rune Forge and Provider suspend their view-owned observation when the entire workspace is hidden. Accepted Rune Forge commands continue while panels are hidden. Provider resume reloads its registry, preserving unsaved LM Studio fields.

Naming requests retain a unique dialog identifier and their originating view and active-layout identity. Superseded requests cannot submit. If the view or active layout changes, submission closes the dialog without changing saved layouts and asks the user to reopen the layout menu.
