## Source contract and remaining qualification

The recorded tools are `process.run`, `shell.run`, `bash.run`, `python.run` and
`powershell.run` in the ordinary MCP path. Managed/provider/runtime identities
keep their existing submission path. `shell_exec` and typed Xcode operations
are not added to this reference set. Existing tool names, argument schemas,
timeouts, output semantics, grants and command replay classes remain required.

`runtime_continuation` is an optional native-associated handoff extension with
schema version 1. It records a scope key, origin epoch and submissions containing
native `submission_id`, actual `job_id` and tool name. The bound is **32 native
submission attempts per logical epoch** and **16 KiB of encoded extension**.
Repeated keyed calls may reference the same job with different attempt IDs;
the limit is not a count of distinct running jobs. The 32nd recorded attempt
requests rollover; capacity is checked again before a CP job can commit.
The extension limit does not qualify the size of every complete MCP response.

The admission sequence is:

1. Forge prepares a one-use native submission UUID against the current Source
   epoch. A blocked epoch or exhausted capacity rejects preparation.
2. RuntimeJobRepository owns the CP `BEGIN IMMEDIATE` transaction. On that same
   connection it rechecks the active ordinary MCP client binding, stable project,
   generation, absence of run/provider/runtime caller identity and the full stored
   authorization scope: canonical/writable roots, tools, network flag and output
   budget. It chooses the actual new or reused job record.
3. Before CP COMMIT, the callback durably appends that actual UUID to Source.
   Source rejects a changed/blocked epoch, consumed attempt or exhausted bound.
   The callback does not enter another CP actor/connection while the writer is
   held. CP then checks caller cancellation and commits; existing persistence
   observers remain after COMMIT.
4. Both early keyed reuse and transactional reuse enter this seam, including
   retained idempotency receipts. The replacement command is not executed.
   The callback is not retained in the reconstructed pending execution request.

Source and CP are separate stores. Source admission may survive CP rollback,
cancellation or later terminal-row/receipt retention. This ordering preserves
the selected UUID, not an atomic two-store commit or proof of command execution.
An unavailable row is **unresolved**, requires attention, and never authorizes
replay. Reference continuity does not infer missing submitted IDs by scanning
all jobs or GUI text and never replays a command.

Fresh packets and current unsealed packet saves merge the latest native
references inside the Source transaction and return the committed packet.
Same-ID sealed or earlier-origin authored edits instead retain their prior
native extension. Budget saves use the eligibility guard above and create a
fresh ID when that predecessor cannot be reused.
Imported/model-supplied extension fields are not admission authority. Old task
text and custom resume seeds remain authored content. Native reference guidance
is carried separately, so retaining an old completed goal does not discard the
newly submitted job. Automatic finalization uses the existing default
`handoff_ready` task status; the original completed authored checkpoint remains
unchanged. Preserving its authored fields does not promise that the finalized
packet status remains `completed`. The current code does not capture a new GUI
user request.

## Resume and current authorization

`get_forge_status(resume=true)` returns the selected persisted packet and may
add `runtime_continuation_status` before clearing the scoped epoch. The sidecar
uses that exact packet's native Source association and submitted IDs; it does
not rewrite the packet or substitute references from the successor's progress.
The active context must match its native scope and authorize `job.status`
(or `*`). An unreadable packet does not grant job access. Each available row
reports current state and an exit code when present; unavailable/unauthorized
rows report unresolved attention with `replay_permitted: false`.

The successor should use the returned UUID with `job.status`, then read stdout
and stderr through `job.read_output`. A queued submission acknowledgement can
refer to a job that has already completed by the time the model reads it.
Output paging, truncation, snapshot and producer-EOF contracts remain separate.

Scoped clearing requires the exact runtime extension to match the predecessor's
current recorded set. Existing acknowledgement/seal fencing remains. Same-ID
authored edits after sealing remain supported; their native origin/reference
extension is retained rather than rebound to successor work. This is not a new
ban on editing authored packet text or a change to the no-redelivery contract.

The implementation uses existing Source progress and packet storage and the
existing CP job/receipt ledger. Reference admission adds **no database schema
migration, Source/CP correlation journal, Source/CP admission lease or reference
retention scan**. The separate runtime lifetime owner repair uses the private
kernel lease and bounded owner inventory described above. Existing storage caps still
apply. Shared stdio identifies the deployment client and Forge logical epoch,
not an authenticated individual external GUI chat.
